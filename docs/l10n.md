# l10n — full en/ko localization

The console is fully localized in English and Korean: UI copy and user-facing
errors both. The server never emits English prose for a user-facing error —
every route returns a stable, dot-namespaced code plus its params, and the web
client renders the localized, interpolated string.

## The error contract

A route responds with `ApiError(code, params)` (`ApiErrors.kt`): a
machine-stable code like `common.not_found` and the params it needs. The web
client looks the code up as an i18n message key. A `code` is the same kind of
stable identifier the repo already uses for Cedar actions (`admin.datasources`,
`stmt.kind.select`) — dot-namespaced, greppable, never localized.

Common failures share one parameterized code instead of a bespoke sentence per
route. `ApiErrors.kt` exposes helpers for them: `badId()` → `common.bad_id`,
`notFound(resource)` → `common.not_found`, `fieldRequired(fields)` →
`common.field_required`, `alreadyExists(resource)` → `common.already_exists`,
`unauthenticated()` → `common.unauthenticated`, `invalidToken()` →
`common.invalid_token`, plus `common.forbidden`. A route mints its own
`<feature>.*` code only when the failure is unique to that workflow —
`approval.already_decided`, `approval.no_execute_role`, `policy.reserved_name`,
`policy.system_immutable`, `datasource.engine_immutable`,
`device.idp_unsupported`.

The catalog key is the code. `messages/<locale>/errors.json` nests to mirror the
dot path exactly (`{"common": {"not_found": "No such {resource}."}}`), so
rendering is `t(code, params)` with no separate mapping layer to keep in sync.

`Scim.kt` is exempt: its error body is the SCIM 2.0 spec's shape, for the IdP,
not this envelope.

## Client: two paths, one catalog

- Imperative. `web/src/lib/api/client.ts`'s `request()` is the only place that
  constructs `ApiError` from a fetch response. It parses `{code, params}` and
  sets the message to the localized string via `translateApiError()`
  (`lib/i18n/errors.ts`). Call sites that do
  `err instanceof Error ? err.message : 'fallback'` (mostly feeding
  `toast.error`) pick up localization unchanged. `translateApiError` is a plain
  function, not a hook — it runs in catch blocks, reads `messages/*/errors.json`
  by direct import, and reads the current locale from a cookie
  (`getClientLocale()`).
- Declarative. The app is wrapped in `NextIntlClientProvider`, and every
  component with user-facing text uses `useTranslations('<Namespace>')` — one
  PascalCase namespace per feature area, matching the nav keys in
  `src/i18n/request.ts`: `Access`, `Audit`, `Common`, `Datasources`, `Errors`,
  `Groups`, `Login`, `Nav`, `Policies`, `Query`, `Session`, `Users`,
  `Workflows`. Each maps to a lowercase file `messages/{en,ko}/<file>.json`
  (e.g. `Nav` → `nav.json`); `request.ts` loads every pair into one messages
  object per request.

## Locale: a cookie, not a URL

There is no `/en/` or `/ko/` route segment — this is an internal admin tool, not
a public site needing locale-distinct URLs. The `NEXT_LOCALE` cookie
(`web/src/i18n/locale.ts`) is read server-side in `src/i18n/request.ts` (via
`next/headers`) and client-side via `document.cookie` (`getClientLocale()`).
`LocaleToggle` (`components/locale-toggle.tsx`, next to `ThemeToggle`) sets the
cookie and calls `router.refresh()` so server components re-render in the new
locale; the imperative error path re-reads the cookie on its next request.
Default is `en`.

## Not covered

- SCIM error responses (`Scim.kt`) — the protocol-mandated shape for the IdP,
  not a human-facing surface.
- Data, not copy — catalog values (table/column/engine names), Cedar
  policy-language source and raw Cedar validation errors, decision/status codes
  shown as literal badges (`ALLOW`/`MASK`/`DENY`, `PENDING`/`APPROVED`), and
  example/placeholder values are not UI copy and are not translated.
- Pluralization / gender / date formatting — `translateApiError` does plain
  `{param}` substitution, not full ICU MessageFormat. No current error code
  needs more; `next-intl`'s ICU engine is reachable from a component if one ever
  does.
